### 1.3 Integer scaling, honestly — the Act 0 screen

The integer law now binds the **Act 0 arcade screen** only. `ScreenFit` picks `k = max(1, floor(min(W/640, H/360)))` and draws the screen grid at exactly `k` display px per texel, centred in the window. **No black bars at any aspect (owner, 2026-11-18):** `ScreenFit.bezel_rect` is the whole window in rig units (hole centred), and the bezel fills it (`BezelField` plus the columns, §2.10). Everything else is native resolution (§1.1).

Grid **256×304** (owner, 2026-11-18; the Williams circuit rotated 90°), hole `(192,28,256,304)` in 640×360 units. Test sizes come from the Steam Hardware Survey (Oct 2026) plus the Steam Deck:

| Window | k | Screen shown at | Note |
|---|---|---|---|
| 1366×768, 1280×800 (Steam Deck) | 2 | 512×608 | |
| 1920×1080, 1920×1200 | 3 | 768×912 | |
| 2560×1440, 2560×1600, 3440×1440 | 4 | 1024×1216 | ultrawide and 16:10 get more bezel, never bars |
| 3840×2160 | 6 | 1536×1824 | |

The tests (`core/ui/tests/test_screen_fit.gd`, `features/cabinet/tests/test_bezel_art.gd`) cover these eight sizes. Weak case: a window just under a multiple (for example 1600×900, k=2) shows the screen smaller against the window; the integer law wins.

We refuse non-integer scaling **of the screen**. A fractional scale blurs a 1 px outline, and the 1 px `VOID-0` outline is the last line of legibility when the warp layers start distorting shape (ART-001 §2). The frame around the screen is the native-resolution bezel (ART-001 §12.7a), not bars. A player who wants a smaller or larger screen gets a different integer step, not a fractional scale; the option is labelled by the multiple it produces. The sim never sees `k`.

**Drawing rule: 1 px lines are drawn pixel-centred (2026-11-18, found in S6).** A 1 px `draw_line` / `draw_polyline` between integer grid coordinates is a 1 px-wide quad through pixel *corners*; on a near-45° run it covers no pixel centre and rasterises **nothing** (the S6 coroner's outline and arrow barbs vanished in a real windowed run while every unit test passed). On the integer grid, 1 px strokes use coordinates offset by +0.5 (pixel centres): `FxLayer.chalk_line_ends(a, b)` / `_chalk_line()` is the reference helper. Regression test: `features/cabinet/tests/test_readable_death.gd` `test_real_entity_death_in_the_real_stage_draws_the_outline_and_arrow` (asserts every chalk endpoint is pixel-centred, since headless has no pixels to read). This binds every 1 px vector on the Act 0 screen and bezel (bezel lines, `VectorText`/`PixelText` strokes, the video-limits work). Existing 1 px strokes elsewhere are not yet audited (a follow-up for their owners); ART-001 §14's Vector row ("coordinates snapped to whole pixels") should gain the same clarification (Visual Design to word it).

### 1.5 GDScript versus native — the honest boundary

| Work | Where it runs | Why |
|---|---|---|
| Movement, lance, charges, Composure, Warp Tier state, Hourglass Clock, spawn budgets, Choir AI state machines, Lantern Tree, save, telemetry, HUD, menus, dialogue, Codex, sector assembly | **GDScript** | all of it is state machines over small numbers, bounded by SYS-001 §3 spawn budgets and §9 contact ceilings — not by arithmetic volume |
| Per-pixel work (light masks, Shroud, warp distortion) | **canvas-item shaders**, GLSL-like Godot shader language | GPU-side; no GDScript pixel loops ever |
| Composite atlas lookups, part pooling | **GDScript**, table-driven | lookups are dictionary hits, not per-pixel work |
| Anything measured over 10,000 objects per frame | would need GDExtension/Rust or C++ | **the ceiling is never reached**: SYS-001 §9 caps on-screen Choir units, entity modules, geodes, hostile contacts, active shots and colliders per sector (all ✱ first-pass rows added 2026-11-17, ruling R-14) |
| A native collision or spatial-hash rewrite | refused for v1 | Godot's 2D physics is expected to be inside budget at SYS-001 §9's collider ceiling; §8.3 measures before we decide |
| Steamworks | GDExtension (`GDSteamworks`, community build, pinned version ✱) | the one exception we accept, because it is a binding, not gameplay code |

**We refuse to write native code for v1.** Not because GDScript is fast, but because nothing in this game's per-frame work is arithmetic-bound: the frame cost is draw calls, shader invocations and scene churn, and those are engine-side regardless of what language authors them. A GDScript hot spot found in §8 profiling gets a data-structure fix or a move to a shader first; a GDExtension rewrite is a documented, logged decision with a profile attached, and no such decision has been taken as of this doc. The single native component we will ship is the pinned Steamworks binding, which contains no game logic and can be stubbed out for non-Steam builds.

Risk we state rather than hide: GDScript is interpreted, and the two places where a naive implementation *would* break budget are the shard-magnet loop (§4.3) and the Ledger Compass redraw (§5.4). Both are designed to be table- and cache-driven in §8.4 rather than per-frame scans. If either misses budget, that is the first candidate for a §11 open question about a GDExtension exception, and it will be a decision with a profile attached, not a refactor done quietly.

### 2.9a VectorText (`core/ui/vector_text/`)

The text engine for everything outside the Act 0 screen (decided in Q-T23, §11.2 row "Q-T23 resolved"; built 2026-11-18, §11.2). `PixelText` stays the face on the 256×304 screen (§1.3); `VectorText` draws at native resolution, sharp at any window size.

| Piece | Role |
|---|---|
| `VectorGlyphSet` (`Resource`) | glyph table: strokes in em units, advance, ink right edge, kerning, baseline, descent, line gap. Data: `data/ui/vector_glyphs.tres` (strokes stored as stroke strings) |
| `VectorFace` (`Resource`) | look at a size: `stroke_width`, `size` (cap height), `tracking` in logical px, plus cosmetic `jitter`, `grain`, `seed` (✱ engineering, no gameplay meaning; jitter and grain come from a local hash of `seed` only, never a gameplay or `warp` RNG stream). Data: `data/ui/vector_face.tres` |
| `VectorLayout` (`RefCounted`) | result: strokes in logical px, `size`, line metrics, line texts, `missing` characters |
| `VectorText` (static, no node) | `layout(text, glyphs, face, align, max_width, glyph_filter) -> VectorLayout` is pure and static; `measure(...)` gives the ink size; `build_mesh(layout, width)` tessellates |
| `VectorLabel` (`Control`) | the node: takes a `tr()` key (or `text` for dynamic text), `face`, `glyphs`, `color`, `alignment`, `wrap` / `max_width` |

- The two `.tres` files carry no `ds_namespace`: they are look data, not tunables, so they are not in the §3.4 registry.
- **Minimum stroke:** `MIN_PHYSICAL_STROKE` = 1.25 physical px ✱. A thinner stroke, especially near 45°, can cover no pixel centre and rasterise to nothing (the same failure as §1.3's drawing rule). `VectorLabel` widens the stroke at draw time from the canvas-to-screen scale; regression test `test_thin_diagonals_never_vanish`.
- **Glyph-lie seam:** `glyph_filter(ch, index) -> char | strokes | null` (a replacement character, replacement strokes in em units, or null to keep the glyph). WARP-001 §4.2 glyph lies plug in through it (via `HudLiar`); the Steady Ledger switches them off. Seam only: no caller yet.
- **`VectorLabel` behaviour:** the layout and the tessellated mesh are cached and rebuilt only when text, key, face, glyphs, size, alignment, filter or language changes. Round caps and joins; edges rely on the root's MSAA 2D (§1.2). Colour stays at or below 1.0, so text never blooms. A translucent colour double-blends where tessellated strokes overlap: fade by modulating the whole control, keep the colour alpha at 1. A character with no glyph draws a box and is listed in `VectorLayout.missing`.
- **Tests** (`core/ui/vector_text/tests/`): layout, wrap, alignment, minimum stroke, glyph filter, label caching, and locale glyph coverage (§7, L10N-001 §5).

## 3. Data resources and `ds_` keys

### 3.1 Layout
`data/<feature>/<name>.tres` — loose `.tres` tunables, one `TunableResource` subclass each. The class script lives with its feature (`features/vigil/vigil_move_stats.gd`) or in `core/` when shared (`core/components/health_stats.gd`). Non-tunable data (route table, theme, bus layout) also lives in `data/` but is not a `TunableResource`.

Create a **Resource** when data is shared, tuned, or authored (stats, items, abilities, Sigils, kits, dialogue lines). Create a **scene** when it needs nodes, a transform, collision or a lifetime. Never put a game number in a script constant.

### 3.2 TunableRegistry
`core/data/tunable_registry.gd`. Not an autoload: `TunableRegistry.new().scan()` walks `res://data`, loads every `TunableResource`, and maps each `ds_` key → (resource, property). Gameplay uses the typed resource directly via `@export`; the registry exists for the lint, debug tooling and save validation.

### 3.3 Data lint
`core/data/tests/test_tunable_registry.gd` fails on: a namespace not starting `ds_`, a malformed key, a duplicate key, a missing required key, a non-positive movement value, `max_hp < 1`. The SYS-001 §10 ↔ key cross-check (every register row ↔ exactly one key) is **not** built: SYS-001 defines no `ds_` keys yet (§11 Q-T03).

## 4. Gameplay runtime

Status for all of §4: **designed, not built** (except where a row says otherwise). This section is the contract the first gameplay features are built against.

### 4.1 The tick
The simulation is the 60 Hz physics tick (§1.2). Every gameplay state change happens in `_physics_process`; `_process` only draws. Order inside one tick is fixed by `process_physics_priority` ✱:

| Priority | Stage | Owner | Reads | Writes |
|---|---|---|---|---|
| −20 | Clock and run timers | `RunSession` (§4.2) | wall tick | Hourglass Clock, Seam timers |
| −10 | Intent | `VigilInput`, Choir brains | devices / AI state | intent fields only |
| 0 | Motors | `VigilMotor`, unit motors | intent, stats | velocity, position (`move_and_slide`) |
| 1 | Geode imaging (M1 sandbox) | `GeodeSandbox` (built, M1 slice 3 PR 3; the priority is set by the sector) | the Vigil's wrapped position (after `SectorWrap` in the same tick) | each geode node's position = the image of its torus home nearest the Vigil |
| 10 | Shots | `ShotSweeper` (§4.6) | shot pool | swept hits queued |
| 20 | Hit resolution | `HitboxComponent` / `HurtboxComponent` | overlaps + queued sweeps | health, `hit_landed` |
| 30 | Economy | `ShardField` (§4.3; built, sets 30 in `_ready`), Sepulchre | shard pool, deposits | shard positions, segment count |
| 40 | Director | `SpawnDirector` (§4.5), `WakingController` (§4.8) | budgets, phase | spawns, stand-downs, phase changes |
| 50 | Warp | `WarpComposer` (§5.1) | tier inputs (WARP-001 §1.3) | active effect set |
| 60 | HUD model | `HudModel` (§5.2) | everything above | the honest readout |

Rule: a stage may read anything earlier in the same tick and anything from the previous tick; it may not write state owned by another stage. Signals emitted inside a stage are handled by listeners in a later stage or deferred.

### 4.2 Where state lives

| State | Class (LOOP-001 §2) | Owner | Lifetime |
|---|---|---|---|
| Seam index, seed, Sigils, Relics, Pact, Charges, Composure, in-run currency | Run | `RunSession` autoload (**planned**, §2.8) holding a `RunState` resource | New Vigil → death / run clear |
| Hourglass Clock, sky count, Hunger, corruption map, telemetry counters | Iteration | `RunSession` → `IterationState` resource | Iteration start → Hard Unmaking |
| Lantern Tree, banked currency, Codex, endings, bests | Anchored | `SaveService` profile slot, loaded into a `ProfileState` resource at boot | forever |
| Per-sector actors, shards, Sepulchre, warp effects | none (rebuilt from seed) | `SectorHost` children | one sector |

Sector scenes never own run state; they receive a `RunState` reference in `on_route_entered(params)` and write back through its methods. That is why a crash costs at most one Seam (LOOP-001 §2).

### 4.3 Shard field and the magnet loop
Shards are the one place a naive implementation scans N×M per frame (the Vigil's magnet plus every Grub looking for glass). **Built in M1 slice 3 PR 3** (`features/charges/shard_field.gd` + `.tscn`, `ShardFieldStats`, `data/charges/shard_field.tres`, keys in §3.4). Numbers are cited from SYS-001 §1.4, not copied:

| Piece | As built |
|---|---|
| Representation | **no node and no physics body per shard** (the earlier design said pooled `Node2D`; dropped: nothing per shard needs a node). Position, velocity, flags (alive, claimed by a Grub) and the last magnet tick sit in packed struct-of-arrays inside `ShardField`, indexed by a fixed pool with a free-slot stack and a dense live list. All positions are torus positions (the sector injects `Torus`; distances use `Torus.delta`) |
| Spatial index | uniform grid of **64 px cells** ✱ (one module, ART-002 §1) over the torus; per-cell intrusive doubly linked lists, updated when a shard changes cell. A torus size that is not a multiple of 64 gets a partial last row/column; a query span that crosses the wrap seam is split |
| Vigil magnet | circle query of SYS-001 §1.4 Shard magnet radius around the collector (the Vigil). Inside the radius the velocity steers toward the Vigil at the SYS-001 §1.4 pull speed and steer rate, **with no drag**; outside, SYS-001 §1.4 shard drag applies (PM-accepted; the Cabinet's `glass_field` was changed to match). Pickup when the distance ≤ Vigil hitbox radius + shard radius + pickup margin (SYS-001 §1.4 rows). With the magazine full the magnet is off and overflow glass stays (SYS-001 §1.4). **H4** (WARP-001 §3.2) = the `magnet_inverted` data flag, no second code path (no H4 caller yet) |
| Collection | one shard = one Charge into `ChargeMagazine.try_add` (cap from SYS-001 §1.4), plus score per shard (SYS-001 §7.1) |
| Grub targeting | hooks `grub_query_due`, `nearest_free`, `claim`, `release_claim`; Grubs may query once per 6 ticks ✱, not every tick. No Grubs call them yet (PR 4) |
| Worst case | pool **144** shards ✱ = 24 geodes (SYS-001 §9 cap) × 6, the detonation maximum (SYS-001 §1.3 detonation 4–6, Q-T29; calm kill 3–5 fits inside). Shards never despawn (SYS-001 §1.4), so the pool is sized for a field of detonations (Q-T59 resolved). **Pool exhausted:** `spawn` returns −1 and increments `spawns_refused`; a live shard is never recycled, nothing crashes |
| Tick | `process_physics_priority` 30, the Economy stage (§4.1) |
| Budget | ≤ 0.3 ms per tick at the worst case ✱ (§8.1); measured by `tests/perf/bench_shard_field` (§8.5) |
| Render | one `MultiMeshInstance2D` for all shards (one draw call) |

**Geodes feeding the field (built, `SectorGeode`, §2.6).** Accepted lance hits only. Calm mining: every SYS-001 §1.3 face-hits shatters a face and frees 1 shard; the last face frees the rest of the calm total (+1 mined bonus), at least 1. Over-fire: SYS-001 §1.3 over-fire hits inside its window detonate the geode (a warning cue once at the warn count); the detonated total (4–6) minus what already came out, at least 1, is drawn from the injected RunSeed `loot` stream (§4.9) and released so each shard comes to rest within the SYS-001 §1.3 scatter radius (release speed capped). Release kinematics and shape are the SYS-001 §1.3 ✱ rows. `GeodeSandbox` lays out the M1 geodes from the `map` stream (seam 0) and shapes from `vfx`, registers each with the `LedgerCompass` (kind `geode`), and each tick moves every geode to the image of its torus home nearest the Vigil (§4.1 priority 1). Cues: `geode_hit`, `geode_crack`, `geode_break`, `overfire_warn`, `overfire_burst`, `magnet_latch`, `shard_chime`, `charge_armed`, `magazine_full` (AUDIO-001 §12.13).

### 4.4 Freezing entities, never physics
The physics server is never paused for gameplay (§1.2 `physics_ticks_frozen = never`); `get_tree().paused` is used only by the pause screen.

| Freeze source | Mechanism | What keeps running |
|---|---|---|
| Anchor field (D-11, SYS-001 §1.1 `anchor_freeze`) | `FreezeComponent.freeze(duration, source_id)` on each unit inside the field (max units per cast from SYS-001 §1.1): disables the unit's brain and motor, zeroes velocity, mutes its chant emitter | its collision shapes (a frozen unit is an obstacle), its hurtbox (it can be killed), budget counting (SYS-001 §1.1 note) |
| Elites / Heralds | same, at half duration (SYS-001 §1.1) | — |
| Sepulchre, The Penitent | excluded by data flag `freezable = false` | everything |
| Pause screen | `SceneTree.paused` | Overlays (`PROCESS_MODE_ALWAYS`) only |
| Codex / cinematics | `RunSession.clock_paused` (Hourglass Clock stops, WARP-001 §6.1 D-01); gameplay is paused by the same tree pause | — |

The freeze timer is owned by the field that cast it, so a unit leaving and re-entering a field cannot double-freeze or extend itself.

### 4.5 SpawnDirector and budgets
One `SpawnDirector` per `SectorHost`. It owns the SYS-001 §4 threat budgets and the SYS-001 §9 on-screen caps (Choir units, geodes, contacts, shots, colliders). Spawns over a cap are queued at off-screen spawn markers (ZONES-001 §1.7 `SpawnMarkerLit/Unlit`). Over the contact cap, the furthest units *stand down* (hold position, keep chanting) rather than despawning, because a vanishing enemy reads as a bug. The Coma mercy (SYS-001 §8) is a SpawnDirector rule keyed on `seam_deaths`.

### 4.6 Pooling and the shot layer
Shots, shards, sparks and chalk flecks are pooled at the SYS-001 §9 ceilings (180 shots both sides). Each shot sweeps a `ShapeCast2D`-equivalent query from its previous to its current position every tick (`PhysicsDirectSpaceState2D.cast_motion` with a pooled circle shape), so nothing tunnels (§2.6). The `ShotSweeper` batches all shots in one stage. Escalation path if it misses budget: batch fewer queries per shot type → grid broad-phase shared with §4.3 → quadtree (GDD §13 owner decision 2026-11-17) → GDExtension only with a profile and a §11 decision.

### 4.7 Choir AI
A unit is a `CompositeRig` (§2.4) + motor + `Brain` component. A `Brain` runs a small state machine whose states are `Resource`s (`state_patrol.tres`, `state_procession.tres`…), so a variant is a data edit. Unit stats and AI budgets come from SYS-001 §3; faction laws (SYS-001 §3.1: shrine ceasefire radius, Acolyte turret lag, Litany Ring) are **asserted** by tests, never left to tuning. Brains tick at 60 Hz for movement and at 10 Hz ✱ for decisions.

### 4.8 WakingController
One per sector with a Sepulchre. Owns the Waking lifecycle phases 0–6 (GDD §8.4, SYS-001 §2), the 20 segment modules and the Unravel hit count. Emits `phase_changed(phase)`, `segment_deposited(index)`, `segment_knocked_off(index)`, `entity_awakened`, `entity_unmade` (EVT-001 rows to add with the code). AUDIO-001's state lines, the HUD and the WarpComposer listen; the controller never calls them. The 1.2 s pre-Awakening silence (GDD §12) is a `phase_changed` consumer in audio, budgeted twice per run by the audio side.

### 4.9 RunSeed, SeedCode and ReplayVerifier

| Piece | Design |

| Location (Q-T28) | `core/rng/`: `RunSeed` (`run_seed.gd`: masking, `stream()`, static `hash64`; there is no separate hash class), `SeedCode` (`seed_code.gd`: encode/decode, checksum). Seeds feed many features (map, warp, loot, AI, generators), so the code is feature-agnostic; `features/run` keeps `RunSession`/`RunState`. Tests in `core/rng/tests/` |
| `hash64` (Q-T26) ✱ | `RunSeed.hash64(run_seed: int, stream_name: String, seam_index: int) -> int` (static, owner ruling 2026-11-18, "M1 chat's version"). `h` = **FNV-1a 64** (offset `0xcbf29ce484222325`, prime `0x100000001b3`) over the UTF-8 bytes of `stream_name`. `x = run_seed XOR h XOR (seam_index * 0x9E3779B97F4A7C15)`. Then the **SplitMix64** finalizer: `z = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9; z = (z ^ (z >> 27)) * 0x94D049BB133111EB; result = z ^ (z >> 31)`. All arithmetic wraps at signed 64 bits; every `>>` is logical (GDScript has no logical shift, so the code masks the vacated high bits). The result is the signed 64-bit int. Constants are built from 32-bit halves because GDScript hex literals above int64 max are not portable. Pure integer maths, so identical on every platform |
| Seeds and `seam_index` (Q-T26) ✱ | `run_seed` is always masked to 55 bits (`RunSeed.SEED_MASK`; `RunSeed._init` masks); a fresh run takes 55 random bits from `Crypto.generate_random_bytes`. `stream_seed = hash64(run_seed, stream_name, seam_index)` with `stream_name` a String from the list above and `seam_index` an **int**: `0` for run-wide draws and when there is no seam (the run's map, world tier, Hunger preset, registry state), `1`–`5` for Seam 1–5 (LOOP-001 §2). The `map` stream uses `0` for the run's map and `1`–`5` for each Seam's layout. `stream_seed` is the full 64-bit result, assigned to `RandomNumberGenerator.seed` by `RunSeed.stream(name, seam_index)` |
| Determinism scope | world tier, Hunger preset and the WARP-001 §3.2 registry state derive from the seed alone (SYS-001 §10 🔒). Cosmetic `vfx` draws are seeded but excluded from verification |
| `SeedCode` | 12 characters of Crockford base32 (no I, L, O, U): 55 seed bits + 5 checksum bits = 60 bits. Displayed as `XXXX-XXXX-XXXX`. A mistyped code fails the checksum and the UI says so in plain words (L10N-001 `MSG_` key) |
| `SeedCode` layout (Q-T26) ✱ | `SeedCode.encode(run_seed, grouped := false)`: value = `(run_seed << 5) \| checksum(run_seed)`, 60 bits, written as 12 symbols **most-significant first** (symbol 12 = bits 4–0 = the checksum). Alphabet in value order: `0123456789ABCDEFGHJKMNPQRSTVWXYZ`. `grouped = true` gives the display form `XXXX-XXXX-XXXX`. `SeedCode.decode(code) -> int` is case-insensitive, strips hyphens and spaces, reads `I`/`L` as `1` and `O` as `0`, and returns `SeedCode.INVALID` (`-1`, never a legal seed) for `U`, any other symbol, a length other than 12, or a checksum mismatch. `is_valid(code)` wraps it. The checksum is the last symbol. Callers show a `tr("MSG_...")` line, never a raw error |
| Checksum (Q-T27) ✱ | `SeedCode.checksum(run_seed)` = **CRC-5**, polynomial x^5 + x^2 + 1 (`0x05`), init 0, no reflection, no final XOR, over the 55 seed bits fed MSB first (owner ruling 2026-11-18; replaces the XOR-of-5-bit-groups checksum, which ignored symbol order and missed adjacent swaps such as `C1SK` vs `1CSK`). Measured, not guaranteed: in the unit test 578/578 sampled adjacent swaps were rejected, and an independent Node check found 0 undetected in 212,958 random swaps |
| Test vectors ✱ | Pinned values from an independent BigInt Node script, matched by the GDScript. `hash64(123456789, "map", 0)` = `-7834688126535706054`; `hash64(123456789, "kits", 3)` = `-1513310087194196715`; `hash64(MAX_SEED = 2^55 - 1, "warp", -2)` = `-2734986135168668244`. SeedCode (CRC-5): seed `0` -> `0000-0000-0000`; `1` -> `0000-0000-0015`; `12345` -> `0000-0000-C1SK`; `2^55 - 1` -> `ZZZZ-ZZZZ-ZZZ4`. `core/rng/tests/test_run_seed.gd` asserts these |
| Cursed seeds | community-shared SeedCodes (GDD §6.3). A SeedCode carries no content version; the game states which content version a seed was minted on if it differs |
| Daily (post-1.0, ruling R-16) | `run_seed` derived from the UTC date `"YYYY-MM-DD"` and an int `content_version`, masked to 55 bits; the derivation is not yet specified (the superseded SHA-256 form is gone; the 3-argument `hash64` does not take a date, so decide when the daily is built); fixed world tier and Hunger preset; H14 never fires (WARP-001 §6.1 D-06) |
| Replay log | seed + content hash + per-tick quantised input: move vector (2 × int8), aim angle (uint16 of a turn), button bitfield (uint16). ≈ 6 bytes per tick ✱ → ≈ 21 KB per minute before compression ✱ |
| `ReplayVerifier` | re-simulates a log headless and compares a state hash (positions rounded to 1/8 px, health, segment count, clock) every 60 ticks. Used by tests and, later, to sanity-check daily scores |
| Honest limit | Godot 2D physics is not guaranteed bit-identical across CPUs and builds. Replays are verified **same build, same platform**. Leaderboards treat verification as a cheat filter, not proof |

## 6. Asset consumption

> **D-13 / D-14 (2026-11-18): the game loads no image or audio files.** Every visual comes from a generator (ART-001 §14) and every sound from synthesis (AUDIO-001 §11). §6.1–§6.4 below describe the retired raster pipeline and remain only as reference. The current rule is §6.5.

Producer side: ASSET-003. This section is what the engine does with the output.

### 6.1 Inputs
(Retired raster inputs, now local-only and Godot-ignored:) `assets/sprites/SPRITE_MANIFEST.csv` (schema: ASSET-003), PNGs under `assets/sprites/generated/<kit>/`, atlases under `assets/sprites/atlas/`, `assets/palettes/darkstar_palette.json`. The manifest CSV is imported with importer **`keep`** (ruling R-19): Godot otherwise treats any CSV as a translation table. Fixed 2026-11-17 in `SPRITE_MANIFEST.csv.import`.

### 6.2 Consumer-side lints (planned as tests in `tests/assets/`)
Naming (ART-002 §2 grammar), palette (every row's colours ⊆ its kit's `kit_locks`, ≤ 10 colours, GASLIGHT only on the three ruling R-06 parts), existence (every `generated` row has a file), size (module multiples of 64 or the row's declared w×h). A lint failure fails the test suite; it never silently substitutes art.

### 6.3 ManifestImporter and AtlasTable (retired, D-13)
`core/assets/manifest_importer.gd` (planned), run headless (`-s`) as the `manifest_import` build step (§1.4). It strips the UTF-8 BOM the generator writes, merges `assets/sprites/SPRITE_MANIFEST_HAND.csv` (hand-authored rows the generator must never overwrite, ASSET-003), and fails on a duplicate id. Atlas sidecar JSON format: ASSET-003 §6.2. It reads the manifest and atlas JSON and writes `generated/sprite_table.gd`: a `const` dictionary `id → {atlas, region, pivot, sockets, frames}` (`AtlasTable`). Runtime code addresses sprites by manifest id only. A missing id in a dev build draws a VOID-5/BONE-5 checkerboard module and logs an error; in a release build the lint above has already failed the build.

### 6.5 Generators (current)
- **Visuals (build time):** pxl renders from `art/src/*.px.js` in `assets/art/generated/` (PNG, sheets, `SpriteFrames` `.tres`), on the palette (D-13 amended, ART-001 §14.8). They load as ordinary textures and swap between tiers.
- **Visuals:** generator classes draw through `CanvasItem` or shaders, with colours from `Pal` (`core/ui/pal.gd`) and text from `PixelText` on the Act 0 screen, `VectorText` everywhere else (§2.9a). A generator is deterministic from its parameters and seed; the WarpComposer (§5.1) feeds it `tier` and `horror`.
- **Sound:** `AudioService` plays the chirp render of each cue (`res://assets/audio/generated/sfx/<id>.wav`, built from `audio/src/*.cx.js`, D-14 amended) and builds an `SfxSynth` fallback lazily, only for a listed cue whose render is missing (AUDIO-001 §12.1; with all renders present, no synth cue is built); renders are mono except the four reverb cues (AUDIO-001 §12.2); long stems and beds render on a worker thread; reactive textures use `AudioStreamGenerator` (AUDIO-001 §11.5).
- **Enforcement:** `tests/test_generated_assets_only.gd` fails if any scene, script or resource under `features/`, `scenes/`, `core/`, `autoload/` or `data/` references a font, an image outside `assets/art/generated/`, or an audio file outside `assets/audio/generated/`; if any render has no matching `.px.js`/`.cx.js` source; if a pxl source does not include a project palette; or if a source uses pxl `image()` or chirp `sample()`.

### 6.4 CompositeRig consumption
`CompositeRig` (§2.4) reads part descriptors (ART-002 §5.1) and instantiates the part generators they name (§6.5); runtime mutation (ART-002 §5.3, the warp's limb swaps) swaps atlas regions on existing `Sprite2D` nodes, never instantiates nodes per frame.

## 7. Save system

### 7.1 SaveEnvelope
`core/save/save_envelope.gd`. A JSON object: `format`, `schema_version`, `slot`, `game_version`, `written_unix`, `checksum` (SHA-256 of the canonical payload), `payload`. Load statuses: `OK`, `MISSING`, `CORRUPT`, `CHECKSUM_MISMATCH`, `NEWER_VERSION`, `WRONG_SLOT`.

### 7.2 Slots and cadence

| Slot | Persistence class (LOOP-001 §2) | Allowed save reasons | Status |
|---|---|---|---|
| `profile` | Anchored | `ruins_entry`, `tree_purchase`, `iteration_end`, `cabinet_score` (Act 0 high score / game over), `cabinet_tape` (coin-slot hazard tape removed; written in attract, never mid-run) | built: Act 0 writes `cabinet_hi_score`, `act0_complete`, `pretence_seen`, `cabinet_tape_peeled` |
| `iteration` | Iteration | `ruins_entry`, `iteration_end`, `new_iteration` | interface built |
| `run` | Run | `seam_boundary` only (never mid-run, SYS-001 §8) | interface built |

Profile flags for endings, Archivist variant and achievements are LOOP-001 §11.7 (invariant IDs). `act0_clean_hands` is evaluated **per Act 0 playthrough** (a replay from the Cabinet starts a fresh evaluation) and only ever sets the profile flag true.

`SaveService.save_slot(slot, payload, reason)` refuses any other reason with `save_failed(slot, &"not_allowed_now")`. Payloads hold invariant IDs and numbers only, never display text. No gameplay writes any slot yet.

### 7.3 Storage, recovery, migration
`FileSaveBackend` writes `user://saves/<slot>.json` via `.tmp` then rename, keeping the previous file as `.bak`. A corrupt or tampered main copy loads from `.bak` (`recovered = true`). A newer schema is refused and never overwritten. Migration: bump `SCHEMA_VERSION`, add one step in `SaveEnvelope.migrate`, never edit a shipped step. `MemorySaveBackend` is for tests. Steam Cloud is a future backend; not built. In test mode the default file root moves under `user://_test/` (§7.4).

Device settings live in `user://settings.cfg` (`SettingsService`), not in a save slot (ruling R-05, §11.1a).

### 7.4 Test isolation
Test runs must never write the player's real `user://` files. `core/save/test_mode.gd` (`class_name TestMode`, static only) ships but is inert in release.
- `TestMode.decide(debug_build, env, args)`: test mode is on only in a debug build AND (env `DARKSTAR_TEST_MODE=1` OR any command-line/user arg contains "gdunit", case-insensitive). An exported release build can never enter it.
- `TestMode.active()` caches the decision. `TestMode.force(on)` overrides it; turning it on wipes `user://_test` once per process, so each run starts from defaults.
- In test mode `SettingsService.settings_path` and the default `FileSaveBackend` root (`SaveService.backend`) redirect to `user://_test/settings.cfg` and `user://_test/saves`. `--no-save` is unchanged.
- Write guard: `TestMode.allow_write(path)` is called at the write chokepoints (`SettingsService._save`, `FileSaveBackend.write_text` and `remove`). In test mode a write to a real player path is refused (`ERR_UNAUTHORIZED`) and recorded in `TestMode.blocked_writes`. Outside test mode it always allows.
- Guard tests: `core/save/tests/test_user_data_isolation.gd` (paths under `user://_test`; the `decide` truth table incl. release = false; a deliberate real-path probe is refused and recorded; `persist = true` lands under `_test`) and `tests/test_zz_user_data_untouched.gd` (runs last; `blocked_writes` must be empty, so a test that hard-codes a real path fails loudly).
- Not verified: a plain windowed launch outside tests (code read only).

**Demo → full game (MARKET-001 §6, PROD-001 M4):** the demo build writes the same slots with the same `SaveEnvelope` schema and an extra payload field `content_scope = "demo"`. The full game reads demo saves through the normal migration path, clears `content_scope`, and keeps every anchored unlock earned in the demo. A demo build refuses a save whose `content_scope` is absent (a full-game save) instead of overwriting it, and says so in plain words. Both builds use the same Steam app data folder only if the demo is a Steam playable-demo branch of the same app (TECH-001 §1.4); otherwise the full game offers a one-time import from the demo folder.

Player-facing failure text: `PlayerMessages.save_message(reason)` → `MSG_SAVE_*` keys. Codes and paths never reach the screen; details go to `push_warning` only.

Troubleshooting: delete `%APPDATA%\Godot\app_userdata\DARKSTAR\saves\` to reset; a `.bak` next to a slot is the previous good copy.

### 9.1 Automation runner (dev/QA)

Placed under §9 because it is a test tool (a scenario runs in the suite and from the CLI); it is not a runtime service, so it is not in §2.8.

**Purpose.** Drive the game from outside the player's hands: scripted input, UI actions, waits, asserts, screenshots. **No networking; D-09 stands.** The runner works in-process (a scenario file read by the game itself); there are no sockets, ports or servers.

**Boundary.**
- Code lives in `core/automation/` (`automation_gate.gd`, `scenario_runner.gd`, `scenario_schema.gd`, `input_driver.gd`, `ui_view.gd`, `capture.gd`, `step_catalog.json`), tests in `core/automation/tests/`. No file declares `class_name`.
- No autoload. `ScenarioRunner` is a child of Boot, loaded **by path**, only if the launch args contain `--scenario=<id>` **and** the build has feature `editor`, `automation_dev` or `automation_qa`. Game code never references it, except Boot's guarded loader.
- New signal: `ScenarioRunner.scenario_finished(outcome)` (dev/QA only; EVT-001).

**Launch.** `godot --path . --fixed-fps 60 -- --scenario=<id> --no-save --out=<dir>`. The Node CLI builds this line: `node tools/automation/darkstar_auto.js validate` and `... run <id> [--windowed]` (see `tools/automation/README.md`).

**`--route=<id>` dev switch (M1 slice 3 PR 1).** `-- --route=<id>` makes Boot start on that routed scene instead of the table's initial route (e.g. `--route=sector` reaches the M1 sector without the Cabinet); combines with `--hull=1|2` and `--no-save`. `LaunchRoute` (`core/routing/launch_route.gd`) resolves it, with the **same gate as the runner** (feature `editor`, `automation_dev` or `automation_qa`); a release build, an unknown id or an empty value falls back to the initial route. `--smoke` ignores it (the smoke run still reaches `'cabinet'`). Routes stay ids from `data/routes/route_table.tres`, never paths.

**Scenarios.** `tests/scenarios/<id>.scenario.json`. The format is checked by `scenario_schema.gd`. **`core/automation/step_catalog.json` is the single source for the step list** (name, arguments, meaning); read it there, do not copy it here.

**Ids.** Ids only, never display text. UI controls: `<route>/ui/<Name>` (for example `attract/ui/NewVigil`). Read-only game state (phase 1): `cabinet/game`, `cabinet/score`, `cabinet/record`; M1 slice 3 PR 1 adds `sector/vigil` (route `sector`; props `vigil_x`, `vigil_y`, `vigil_speed`, `hull_max_hp`, `camera_x`, `compass_markers`; later `camera_gap`, `facing_deg`, `aim_x`, `aim_y`), used by `tests/scenarios/m1_sector_feel.scenario.json`. M1 slice 3 PR 3 adds `sector/field` (route `sector`; props `geodes_alive`, `geodes_detonated`, `shards_free`, `charges`, `score`) and three suite-eligible scenarios: `m1_geode_mine` (aim right, feathered fire: calm mining frees glass, no detonation, no Charge), `m1_magnet_collect` (mine, fly in, the magnet collects: ≥ 1 Charge, score ≥ 200), `m1_overfire` (move up onto a 3-face geode's row, aim right with `mouse_move`, held fire: one detonation, ≥ 4 free shards). They rely on the sandbox seed (SYS-001 §1.3 "M1 sandbox geode layout"). `m1_mouse_aim` (`mouse_move`, then asserts `sector/vigil` `facing_deg`, `aim_x`, `aim_y`) covers the mouse path. A control's `<Name>` is its scene-unique `%Name` (UI-001 §7, §8).

**Mouse aim and injected input.** On the root window, `Viewport.get_mouse_position()` reads the OS cursor whenever the display server has a mouse (any windowed run), so motion injected with `Input.parse_input_event` (scenario `mouse_move`, replays) never reached aim windowed. Measured: injected logical (100, 60) while `get_mouse_position()` returned (838.5, -180) from the real cursor; headless falls back to Input's position, so it worked there. `VigilInput` now records each `InputEventMouseMotion` position in `_input` without consuming it (already logical 640×360 viewport space, root stretch undone) and converts it with the canvas transform inverse (`VigilInput.viewport_to_canvas`), the same mapping a real mouse gets. It falls back to `get_mouse_position()` before the first motion event; the right stick keeps priority. Real-player differences: aim holds the last in-window point while the cursor is outside the window; motion during pause is picked up on the next move. Scenarios should `mouse_move` right after the sector loads. Covered by `features/vigil/tests/test_vigil_input.gd` (7) and `tests/scenarios/m1_mouse_aim.scenario.json`. Follow-up (small, not done): `core/automation/step_catalog.json` calls `mouse_move` coordinates "window coordinates", but they are logical 640×360 (`input_driver` converts); fix the wording there.

**Determinism.** Waits count physics frames, each with a `within` limit. The CLI launches with `--fixed-fps 60`. The GdUnit path has no fixed-fps and asserts the outcome only (pass or fail), never frame counts or timing.

**Safety.**
- The runner refuses (exit 3) unless `SaveService.backend` is a `MemorySaveBackend`; it sets `SettingsService.persist = false` and resets settings to defaults before the first route.
- `--out` must be under `user://` or the project `reports/` folder, with no `..`; a bad path is refused (exit 3).
- No `eval`, no expression language, no console command execution: steps come only from the catalog.
- Held input is tracked in a ledger; every held key, button or mouse button is released when the scenario ends, on any outcome.

**Result.** `reports/automation/<id>-<stamp>/` holds `result.json`, screenshots and `console.log` (generated, not source). Exit codes: 0 pass; 1 fail or timeout; 2 invalid scenario; 3 refused (saves not in memory, or `--out` outside the allowed folders); a build without the feature tags prints one line and boots normally, ignoring `--scenario`; CLI only: 4 watchdog, 5 crashed.

**Capture scenarios.** `tests/scenarios/sizzle_s5_surge.scenario.json` (S5 Surgelight afterimage and wake, §2.10; suite-eligible, `screenshot` steps skipped headless).

**Suite adapter.** `tests/test_scenarios.gd` runs scenarios headless inside the GdUnit suite. It allows only scenarios with `args: []` and `timeout_frames` ≤ 1200 ✱.

**Aether scenarios (2026-11-18).** `tests/scenarios/aether_gallery_tiers` (steps through the tier exhibits) and `tests/scenarios/aether_gallery_entity` (the entity-presence exhibit) open the dev route `aether_gallery` with `goto`, so they only run in a dev build (§2.1). Both are suite-eligible; headless runs skip `screenshot` steps, so the windowed capture, the `AETHER_COST` line and any pixel checks happen only with `--windowed` (§11.1 Q-T64). Related tests: `features/aether/tests/*`, `scenes/dev/aether_gallery/tests/*`, `tests/test_dev_routes_gate.gd`.

**Known limitations.**
- `--headless` has no renderer: `screenshot` steps are skipped. Use a windowed run (`--windowed`).
- Scenario args are read from the real command line only (Q-T47).
- The suite adapter limits above apply.
- Cabinet entity ids, a state probe and the cabinet-touching dev steps (teleport, spawn, kill_all, set_lives, set_stage, step_sim) are not built (phase 2, Q-T49).
- Recorder replay is faithful only with the same stage seed, save state and `--fixed-fps 60`; determinism is not verified beyond a ±2-frame replay test. Raw keys not mapped to actions are not recorded.
- Headless runs that quit on the attract route end with Godot's "ObjectDB instances were leaked" and "resources still in use" lines. Cause not investigated; harmless (Q-T54).

**Profiles and presets.**
- Profile `dev` = build feature `editor` or `automation_dev`; profile `qa` = feature `automation_qa`. Catalog steps marked `"dev": true` are refused in QA (exit 3, before frame 0). A scenario may declare `profile` and can only ask for less: qa on a dev build is held to qa; dev on a qa build is refused. `result.json` holds `profile` (effective) and `build.profile`.
- QA saves: fixtures must be listed in `tests/fixtures/saves/approved.json`.
- New steps: `set_setting{key,value}` (dev only; SettingsService accessibility keys only); `reset{}` (both profiles: clears memory saves, resets settings, back to attract).
- `Windows Desktop` excludes `core/automation/*`, `features/*/automation/*`, `tests/*`, `core/*/tests/*`, `features/*/tests/*`, `scenes/tests/*`, `scenes/dev/*`, `data/routes/dev_*` (reserved for dev-only routes, added with the Aether gallery), `addons/gdUnit4/*`, `addons/godot_ai/*`, `reports/*`; `data/` stays shipped. `Windows QA` (feature `automation_qa`) includes `core/automation/step_catalog.json`, `tests/scenarios/*.json`, `tests/fixtures/saves/*.json` (json is not a resource, so it needs `include_filter`) and excludes test code, `tests/support/*`, gdUnit4, godot_ai, `reports/*`. The godot-ai export plugin strips its `_mcp_game_helper` autoload in headless export.
- Guard test `core/automation/tests/test_export_presets.gd`: every non-automation preset excludes the required globs and has no automation feature; the QA preset has `automation_qa`, the json includes, excludes gdUnit4/godot_ai, keeps scenarios and fixtures; each `core/automation` and `features/*/automation` folder is covered by the release excludes; no credential-like non-empty keys.
- Pack audit: `--export-pack "<preset>" build/audit/<x>.pck`, then `node tools/automation/pack_audit.js <file.pck> --profile release|qa` (exit 0 pass, 1 fail). Release must hold no automation, tests, gdUnit4, godot_ai, scenarios or fixtures; qa must hold the runner, `step_catalog.json`, scenarios, `approved.json`, and no gdUnit4, godot_ai or test code.
- Recorder: `-- --record=<id> --no-save [--out=<dir>]` (dev profile, memory saves only) writes `<out>/<id>.scenario.json` on exit: InputMap action press/release, mouse buttons and position, idle frames collapsed to `wait_frames`.

### 9.2 CI (GitHub Actions)

File: `.github/workflows/ci.yml` (job `checks`). Status: added 2026-11-18; the first run is the PR that adds it, so it is not yet shown to pass.

**Setup.** Runs on every pull request and on pushes to `main`, on `ubuntu-latest`. Timeout 25 min ✱. Token is read-only (`permissions: contents: read`); no secrets. Concurrency cancels older runs of the same ref.

**Steps.**
1. Check out without LFS. Cache the LFS objects (key = hash of `git lfs ls-files -l`), then `git lfs pull`. Only generated audio is in LFS (about 25 MB, 45 files); on a cache hit nothing is downloaded, so no LFS bandwidth is used.
2. Download Godot 4.7.2-stable (Linux zip, official release), check it against a pinned SHA-512, cache the binary.
3. `--import`.
4. The GdUnit4 suite (`-a core -a features -a scenes -a tests`).
5. Boot smoke (`--smoke --no-save`): must print `BOOT_SMOKE: reached route 'cabinet'` and have no ERROR or WARNING lines.
6. Every `tests/scenarios/*.scenario.json`, headless, through `node tools/automation/darkstar_auto.js run <id> --godot=<exe> --keep` (§9.1).
7. On failure, upload `reports/` and `smoke.log` as an artifact (7 days).

Actions (checkout, cache, upload-artifact) are pinned to full commit SHAs (tags resolved 2026-11-18).

**Not in CI.** Exports and pack audits (they need the 1.2 GB export templates); a Windows runner (planned later, on demand or nightly: Windows minutes cost 2x and Windows is the ship target); screenshots (headless has none); the Web export.

**Cost.** Private-repo free-minutes allowance; Linux minutes count 1x. A run is expected to take about 5-10 minutes [estimate; measure from the first run].

**Run the same checks locally.** The commands are in CLAUDE.md §4 (import, suite, smoke), plus `node tools/automation/darkstar_auto.js run <id>` for scenarios.

**Update pins.**
- Godot: change the version and the SHA-512 together in `ci.yml` (take the hash from the official release's `SHA512-SUMS.txt`); bump the cache key with it. Keep it equal to the version in CLAUDE.md §4.
- Actions: resolve the new tag to its full commit SHA and replace the pinned SHA; keep the tag in a comment.

**Required check (recommendation).** After the first green run, the owner may mark the `checks` job required in branch protection. Owner's decision; not changed here.
